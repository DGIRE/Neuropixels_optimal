Autonomous INTAKE + CONTRACT prompt (Claude Code CLI, Phase 1)
=============================================================
Produces a rendered, review-ready contract from a specified request, with no
per-command approvals, and STOPS at the human approval gate.

HOW TO USE
  1. Activate the vras venv and set RW_PY in that shell (drives hooks + analysis):
       $env:RW_PY="C:/Projects/Repos/Agentic Research/Research Setup/research_workflow/vras/Scripts/python.exe"
  2. Make sure the request document is already at
       C:\Projects\Repos\Neuropixels\_pipeline\<TASK-ID>\01_request\<TASK-ID>_request.docx
     and is SPECIFIC (see Appendix B of the autonomous manual) so no open decisions arise.
  3. Confirm .claude\settings.json AND .claude\hooks\block-dangerous-bash.py are in place;
     launch claude once, do one edit, confirm NO "hook error" lines.
  4. Launch headless in bypass mode from the project, with <TASK-ID> and the request path filled in:
       cd C:\Projects\Repos\Neuropixels
       claude -p "<paste the PROMPT below>" --permission-mode bypassPermissions

------------------------------ PROMPT (fill <TASK-ID>; paste verbatim) ------------------------------

Autonomously prepare the contract for task <TASK-ID> in project
C:\Projects\Repos\Neuropixels, then STOP for human approval -- do NOT approve.

Run these steps in order, using research_workflow's --project flag (never `cd ... &&`),
and run any python as "$RW_PY" (never bare python / py / anaconda):

1. research_workflow --project C:\Projects\Repos\Neuropixels init   <TASK-ID> --risk red
   (skip if the task already exists.)
2. research_workflow --project C:\Projects\Repos\Neuropixels ground <TASK-ID>
3. research_workflow --project C:\Projects\Repos\Neuropixels ingest <TASK-ID> ^
      --request "C:\Projects\Repos\Neuropixels\_pipeline\<TASK-ID>\01_request\<TASK-ID>_request.docx"
   Confirm the request's data line was captured as a DATA-* item.

4. Act as the CONTRACT-DESIGNER. Author
   C:\Projects\Repos\Neuropixels\_pipeline\<TASK-ID>\contract_spec.yaml to research_workflow's
   schema (task_id, contract_version, analysis{...}, figures[...], report OR reports{...},
   acceptance_criteria, data_provenance, open_decisions). REUSE the conventions of the most
   recent APPROVED contract in this project (read _pipeline\NP-DEMO-2\contract_spec.yaml as the
   template): SNF-not-LFP (PROH-001), valid-sniff-only exclusion, MRL + preferred phase, unit
   inclusion < 0.1 Hz or < 50 valid-sniff spikes, unit-level linear mixed-effects (condition
   fixed, animal random intercept; standardized effect size; no per-unit FDR), animal-level
   paired exact Wilcoxon + rank-biserial r, the QC + results figure set, and the two-document
   report (methods_report + results_report). CHANGE ONLY what THIS request specifies differently
   (e.g. a different ethanol-detection rule, examples metric/k, QC-PSTH basis). Pin data_provenance
   from the request's DATA item. Put EVERY genuinely unresolved scientific choice in open_decisions
   -- do NOT guess or invent a method the request did not state. Write the yaml to a file; do not
   use `python -c` heredocs.

5. research_workflow --project C:\Projects\Repos\Neuropixels contract <TASK-ID> ^
      --spec "C:\Projects\Repos\Neuropixels\_pipeline\<TASK-ID>\contract_spec.yaml"
6. research_workflow --project C:\Projects\Repos\Neuropixels status <TASK-ID>

7. If status shows open decisions (> 0) or the contract did not reach AWAITING_HUMAN_REVIEW:
   STOP and report the exact open_decisions / error for the human to resolve in the request.
   Otherwise report: "Contract for <TASK-ID> rendered (yaml_sha ...), state AWAITING_HUMAN_REVIEW,
   0 open decisions -- ready for review at 02_contract\contract_v001.docx." Do NOT run approve.

Do not edit anything under Optimized Python\ or Golden Fixtures\ or any tolerance config. If any
step errors, STOP and report it; do not improvise around a hook block.
